**Approach chosen: abort-with-clear-message.** Re-merge rejected as risky: `apply` only gets `&amp;AdoptionPlan` — it does not hold the `AdoptOptions`, `DetectionReport`, or drafted-constitution needed to recompute a merge, so re-merging would mean re-running the whole detect→propose pipeline inside `apply`. **How guard works.** `propose` now records, for every merge write (`Append`/`MergeJson` mode only — `Create` writes replace wholesale and are already gated by blockers), the file content it merged against at detect time. Stored on `AdoptionPlan.source_guards: Vec&lt;SourceGuard&gt;` where `expected: Option&lt;String&gt;` — `Some(content)` means "must match", `None` means "was absent, must stay absent". `apply` calls `revalidate_sources` right after the blockers/preflight checks and before any staging: it re-reads each guarded file and, on any divergence (edited, created, or deleted), returns `AdoptError::StaleDetection` with the message `files changed since detection (&lt;paths&gt;); re-run \`derrick init\``. No promotion happens, so external edits are never clobbered. Guards derived from actual plan writes, so no false-positive aborts on files that don't feed a write (README/CONTRIBUTING/ADRs read only for constitution drafting are not guarded).
