# derrick workspace — cross-crate architecture assessment

Read-only. 22 crates, clean layered DAG (substrate → config only; native → substrate+stack+config; no cycles). Evidence is `file:line`.

## Strengths

1. **Layered, composable error model.** Per-crate typed `thiserror` enums fold into a single boundary error via `#[from]`: `RunError` absorbs `SubstrateError`/`HostError`/`ModelError` (`derrick-assay/src/types.rs:189-228`). Public error enums are `#[non_exhaustive]`; the substrate leaks nothing concrete — backend faults are boxed at the seam (`SubstrateError::Backend(Box&lt;dyn Error + Send + Sync&gt;)`, `derrick-substrate/src/types.rs:49-52`). Textbook "typed inside, boxed at boundaries."

2. **`Substrate` as an event-sourced state machine, not a CRUD bag.** Generic `set_ticket_state` is deliberately narrowed to the no-op idempotency path, with every real transition getting a dedicated typed method that refuses illegal moves (`assign_to_hand`, `transition_to_in_review`, `verify_ticket_merged`, `block_ticket`, …) — `derrick-substrate/src/lib.rs:46-160`. The doc comments encode the state graph and TOCTOU handling (`unblock_ticket` re-verifies inside the txn). Invariants enforced at the API surface.

3. **`StackBackend` extension-seam discipline.** New capabilities ship as default methods returning `StackError::NotSupported` so the trait stays stable and existing backends keep compiling (`derrick-stack/src/lib.rs`, `retarget_pr`/`set_pr_body`/`pr_body`). Doc comment names both implementors and the §8.6 rationale. This is the working-agreement pattern done right.

4. **`Model` trait is genuinely narrow.** `stream` is the one primitive; `complete` is a provided default that drains it (`derrick-models/src/lib.rs:22-75`). Small surface, `#[non_exhaustive]` event/finish enums, cost accounting isolated behind `CostHint`.

5. **Strict, enforced workspace hygiene.** `unsafe_code = "forbid"`, clippy `all=deny`/`pedantic=warn`, `unwrap/expect/panic/print_* = deny`, edition 2024, tuned release profile (`Cargo.toml`). The few production `expect`s carry invariant-documenting messages ("built-in symbols query must compile", `derrick-survey/src/parse/mod.rs:46`) — deviations are justified, not accidental.

## Improvements (prioritised)

1. **[HIGH] The `Substrate` trait is largely vestigial — the real seam is the concrete `NativeSubstrate`.** Executor and UI crates hold `Arc&lt;NativeSubstrate&gt;`, not `Arc&lt;dyn Substrate&gt;` or a generic `S: Substrate`: 43 concrete uses vs 6 `dyn Substrate` workspace-wide. The foreman itself is concrete (`substrate: Arc&lt;NativeSubstrate&gt;`, `derrick-substrate-native/src/foreman.rs:565`), as are every dispatcher (`derrick-hand/src/lib.rs:155`, `derrick-claude/src/dispatcher.rs:86`, `derrick-copilot/src/local_dispatcher.rs`). Consequences: (a) the abstraction can't be substituted exactly where it would help — tests and alternative backends; (b) `derrick-hand/claude/copilot/tui/observe` all hard-depend on `derrick-substrate-native`, so the trait buys no decoupling. Decision for `design-keeper`/`substrate-engineer`: either route callers through `Arc&lt;dyn Substrate&gt;` and make the trait load-bearing, or accept there is one backend and retire the 47-method trait rather than maintain a fiction. Right now you pay the trait's cost without its benefit.

2. **[HIGH→MED] `Substrate` is a god-trait — 47 async methods** spanning tickets, batches, links, hands, events, foreman lifecycle, and worktree reservations (`derrick-substrate/src/lib.rs`). This violates the "narrow traits, one or two methods" agreement and inflates every implementor and mock. Split into role traits (e.g. `TicketStore`, `EventLog`, `HandRegistry`, `ForemanState`, `WorktreeReservations`); callers then depend only on the slice they touch, which also makes the `dyn` migration in #1 far cheaper.

3. **[MED] Dead-weight deprecated methods still on the public trait.** Four `#[deprecated]` methods (`record_event`, `tail_events`, `record_foreman_start`, `record_foreman_stop`) carry "will be removed after T012" notes while the surrounding docs already speak of T012 in the past tense (`derrick-substrate/src/lib.rs:227-305`). Every backend and test double must still implement them. Schedule the removal cut.

4. **[MED] `Model::complete` default masks stream-truncation.** If a stream ends without an `End` event, the default drains to `FinishReason::Stop` with `tokens_in/out = 0` rather than surfacing the defined `FinishReason::Error` (`derrick-models/src/lib.rs:48-75`). A provider that dies mid-stream reads as a clean empty completion — a silent correctness gap in the shared default that all providers inherit.

5. **[LOW] Observability surface reaches into the concrete backend.** `derrick-observe` and `derrick-tui` (read-only views) depend on `derrick-substrate-native`. Same root cause as #1; resolving #1 removes this coupling for free.

## Notable-but-fine

- `HandDispatcher` trait lives in `derrick-substrate-native/src/foreman.rs:236` (foreman owns dispatch), taken as `Box&lt;dyn HandDispatcher&gt;` and `StackBackend` as `Arc&lt;dyn StackBackend&gt;` in `Foreman` — those two seams *are* polymorphic and correct. It's specifically the substrate handle that's concrete, which is the one that matters most.

## Substrate assessment: `derrick-substrate` + `derrick-substrate-native`

### Strengths

**1. D31/D33 merge-observation is enforced at the storage boundary — no optimistic close exists.**
Crew-mode `Done` is reachable only through `verify_ticket_merged` (requires `InReview`, stores `merge_sha`; `lib.rs:966-1017`) or `reconcile_ticket_done_from_git` (requires `Ready` *and* a prior `TicketTransitionedToInReview` event; `lib.rs:1222-1284`, evidence check `ticket_has_in_review_event` at `2354-2367`). The verifier confirms with `git merge-base --is-ancestor` (`foreman.rs:115-132`) and, on the squash path, re-checks that the gh-reported merge SHA actually lands on target before closing (`foreman.rs:929-951`). If gh says merged but the SHA is not on target it escalates and leaves the ticket `InReview` (`foreman.rs:955-966`). This is exactly the D31 anti-goal guard.

**2. Cross-process lost-update protection via conditional UPDATE.**
`assign_to_hand` does not trust its own `SELECT`: it gates the write on `WHERE id=? AND state='ready'` and treats a 0-row result as a `Conflict`, aborting the whole transaction so no assignment events get written on a lost race (`lib.rs:828-846`). The comment correctly notes the tokio writer mutex does not span processes (daemon + CLI). Same pattern used for batch/worktree closes.

**3. kind/body event consistency + ticket-as-projection.**
Every event flows through one writer (`insert_typed_event_with_kind`, `lib.rs:2546-2581`) that serializes the discriminator column and the full tagged-JSON body together, so they cannot diverge. Each state transition writes its domain event *and* a `TicketStateChanged` in the same transaction (e.g. `transition_to_in_review` `lib.rs:934-958`), so the ticket row is a rebuildable projection of the log. Legacy-row decode fallback is handled defensively (`decode_event_body`, `lib.rs:2788-2844`).

**4. Migration discipline is genuinely migration-safe.**
Table-rebuild migrations (0002, 0003) toggle `foreign_keys=OFF` *outside* the transaction (SQLite ignores it inside), run `PRAGMA foreign_key_check` inside, and re-enable FKs in a finally-style block even on failure (`lib.rs:2142-2223`). `user_version` gating plus a "newer than supported" refusal (`lib.rs:2080-2087`). CHECK constraints keep DB enums in lockstep with Rust `FromStr` (migrations 0003/0004). Additive migrations are documented as rebuild-free.

**5. Liveness = pid + heartbeat, with correct precedence (D75).**
Cleanup treats a dead pid as authoritative (abandon even if heartbeat is fresh), lets a live pid suppress stale-heartbeat abandonment, and falls back to pure TTL for no-pid hands (`foreman.rs:744-784`). `kill(pid,0)` implemented inline to avoid a libc/nix dep. Every long-lived state has a reconciliation pass (worktrees, adopt-stage dirs, abandoned hands, stale `InReview`, `Ready`-with-history) — satisfies D32.

### Improvements (prioritised)

**1. [HIGH] The foreman provides no backstop for the `Ready→InFlight` transition — it fully trusts each dispatcher to assign.**
`dispatch_ready` (`foreman.rs:1305-1368`) computes `budget = batch_max - inflight`, lists `Ready` tickets, dispatches, and in phase 3 only inspects the `Result` variant. It never uses `DispatchResult.hand` and never verifies the ticket actually left `Ready`. If any `HandDispatcher` returns `Ok` without calling `assign_to_hand` (a bug, a partial failure after spawn-but-before-assign, or a future adapter), the ticket stays `Ready` and is re-dispatched every tick — duplicate hands, duplicate worktrees, and branch-name collisions for one ticket. The whole no-double-dispatch guarantee currently lives in convention inside each dispatcher (confirmed: test dispatchers all call `assign_to_hand` and swallow the `Conflict`, `foreman/tests.rs:205-218`). Fix: have the foreman assert the ticket is no longer `Ready` after a successful dispatch, or move the `assign_to_hand(ticket, result.hand)` call into the foreman itself so the substrate boundary — not the adapter — owns the claim.

**2. [MED-HIGH] Worktree TTL prune can yank the checkout out from under a live, long-running hand.**
`list_stale_open_worktrees` filters only on `closed_at IS NULL AND created_at &lt; threshold` (`lib.rs:371-392`); cleanup step 1a then runs `git worktree remove --force` on it (`foreman.rs:694-732`). It does not check whether the owning ticket is still `InFlight` or whether the hand's pid is alive. `created_at` is only refreshed on (re-)reservation, not on heartbeat, so a legitimately heavy ticket whose hand works past `worktree_ttl` (default 24h) loses its worktree mid-run. Fix: exclude `ticket:`-keyed worktrees whose ticket is non-terminal and whose hand is still alive, or refresh `created_at`/gate on hand liveness rather than raw age.

**3. [MED] Every mutation opens a brand-new SQLite connection.**
`run_write` calls `open_writer_connection(&amp;db_path)` on each call (`lib.rs:620-634`), paying connection open + three `pragma_update` round-trips (`configure_common_pragmas`, `2063-2074`) per write. Under the foreman's poll loop (which emits many events per tick) this is avoidable churn and also means the writer never benefits from a warm page cache or prepared-statement reuse. Since the tokio writer mutex already serializes writes, hold one persistent writer `Connection` behind the mutex instead of reopening.

**4. [LOW-MED] Abandoned hands are never deregistered; hand rows and dead pids accumulate.**
Cleanup 1c releases an abandoned hand's tickets (`foreman.rs:754-783`) but leaves the hand row with its stale heartbeat and dead pid. `list_hands` (rescanned every tick) grows unbounded over a long-lived site, and a dead-pid hand is re-evaluated forever. Consider clearing the pid on abandonment and/or a retention pass for hands with no owned tickets past a TTL.

**5. [LOW] `batch_max` bounds only `InFlight`, not `InFlight + InReview`.**
`dispatch_ready` caps on `count_inflight_tickets` alone (`foreman.rs:1306`, `lib.rs:461-473`). Tickets in `InReview` still hold a worktree and an open PR but do not count against the cap, so the number of concurrently-open worktrees/PRs can exceed `batch_max`. If the cap is meant to bound "active hands" this is correct; if it is meant to bound resource footprint (worktrees/PRs), it under-counts. Worth confirming intent against §9.C and documenting. Related minor: event ordering leans on RFC3339 *text* comparison in `tail_typed_events` (`lib.rs:1806-1839`) — safe today because all timestamps are UTC and `rowid` is the tiebreaker, but `to_rfc3339()`'s variable fractional-second precision makes pure `at` ordering fragile; the order-critical reads correctly use `rowid` (`most_recent_in_review_metadata`, `lib.rs:557`), so keep it that way.

## derrick-tools / -models / -copilot / -claude / -hand / -assay — read-only assessment

### Strengths

1. **Secret-redaction discipline is consistent and matches the working agreement.** `Secret` never `Debug`-prints (`derrick-models/src/lib.rs:261-281`); `HostRequest` has a hand-written `Debug` that redacts the prompt and prints only an env-var count (`derrick-tools/src/lib.rs:175-191`); `HttpApiModel` deliberately derives no `Debug` and the key is only ever attached as a header, never serialised into body/error/log (`derrick-models/src/providers/api.rs:141-148`).

2. **Subprocess mechanics in `process.rs` are correct where it's easy to get wrong.** stdout+stderr are pumped on separate tasks to avoid the pipe-buffer deadlock, with `kill_on_drop`, a wall-clock timeout, `NotFound` classification, and byte-identical capture alongside live line-streaming (`derrick-tools/src/process.rs:62-114`). The no-pre-check rationale is documented (`:22-26`).

3. **Retry/fatal classification is principled and typed end-to-end.** `ModelError::is_retryable` (`derrick-models/src/lib.rs:324-336`); spawn-vs-transient `io_kind_is_retryable` so `PermissionDenied`/`NotFound` don't burn retries (`host_delegated.rs:100-144`); HTTP 429+5xx only (`api.rs:557-560`); and overflow-safe, 30s-capped backoff (`lib.rs:551-555`). `#[non_exhaustive]` fall-through handled (`host_delegated.rs:137-143`).

4. **Assay is genuinely fail-closed.** Multi-reviewer quorum requires every configured reviewer to produce a parseable verdict; partial skip = quorum failure, reviewer error halts immediately (`derrick-assay/src/lib.rs:247-304`), and `reconcile_verdicts` refuses an empty outcome set (`:914-920`). `parse_verdict` is strict — standalone-declaration only, rejects substring-in-prose and fails closed on two distinct verdict words (`:1041-1106`).

5. **The API streaming parser is robust to real wire messiness.** SSE frames split mid-chunk are reassembled, a dangling frame with no terminating blank line is flushed at EOF, `[DONE]`/keepalive/unparsable frames are tolerated with a warn, three dialects share one decoder (`api.rs:288-461`), all covered by focused tests.

6. **Catalogue tier fallback never silently escalates** above Standard, with an explicit regression test for the old `tiers.last()` bug (`derrick-tools/src/catalogue.rs:62-77`, test `:428-442`).

### Improvements (prioritised)

1. **API provider never emits `FinishReason::Length` — truncated responses look like clean stops (medium-high).** `stream()` hardcodes `finish_reason: FinishReason::Stop` at end-of-stream (`api.rs:645-649`), and `interpret_openai`/`interpret_anthropic`/`interpret_ollama` decode only `Delta` + `Usage`, never the provider's `stop_reason`/`finish_reason`/`done_reason` (`api.rs:464-531`). A response cut off by `max_tokens` is indistinguishable from a natural completion for any caller inspecting `finish_reason` (only the `shell` provider ever reports `Length`). Map the dialect stop-reason into the terminal `End`.

2. **`headless` is silently ignored by the copilot (and codex) adapters, breaking the documented contract (medium).** `HostRequest::headless` is documented to map to a no-interactive flag "for other hosts" (`tools/lib.rs:135-143`), but `copilot.rs:50-70` never reads it — it relies solely on the orthogonal `copilot_tools` knob, forcing every caller to special-case `if host_name == "copilot" { copilot_tools = AllowAll }` (`flow/src/steps.rs:281-283`). The generic `HostCliHandDispatcher` sets `headless = true` but never touches `copilot_tools` (`hand/src/lib.rs:476`), so routing copilot through it would hang on tool-approval prompts. Currently latent only because `host_name_for_kind` excludes copilot (`cli/commands/foreman.rs:289-296`). Either honour `headless` inside the copilot adapter or drop it from the trait contract for that host.

3. **`shell` provider can convert a valid completion into an error (medium).** After a valid `&lt;&lt;DERRICK-META&gt;&gt;` line it emits the `End` event and `break`s (`shell.rs:199-204`), then unconditionally re-waits the child and, on any nonzero exit, pushes a `Provider` error too (`shell.rs:222-244`).
